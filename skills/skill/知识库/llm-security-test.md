# LLM / Agent 安全审查（2026）

> status: current  
> last_reviewed: 2026-09  
> scope: LLM 应用、RAG、Agent、工具调用、MCP、长期记忆

本专题不把“聊天越狱成功”本身当作高价值漏洞。真正需要关注的是模型输出是否跨越了身份、数据、工具或执行边界。

## 1. 威胁模型

按五层拆分：

1. **输入层**：用户提示、网页/邮件/文档等间接输入；
2. **检索层**：RAG、向量库、搜索索引与外部数据源；
3. **模型层**：系统提示、策略、上下文与输出；
4. **工具层**：浏览器、代码执行、文件、数据库、SaaS、MCP；
5. **状态层**：会话历史、长期记忆、任务状态和缓存。

漏洞判断要落到某一条真实安全边界，例如：跨用户数据、未授权工具动作、错误权限继承、敏感数据泄露或持久化污染。

## 2. 2026 优先检查面

### Prompt Injection

区分直接与间接 Prompt Injection。后者来自网页、邮件、PDF、工单、代码仓、搜索结果等不可信内容，是 Agent 系统的主要风险之一。

防御审查重点：

- 不可信内容是否与系统/开发者指令明确分层；
- 工具参数是否经过结构化校验；
- 高影响动作是否需要独立授权；
- 模型是否能把外部内容提升为策略或权限来源。

### Sensitive Information Disclosure

检查系统提示、连接器数据、检索片段、密钥、内部标识和跨用户会话是否可能被不必要暴露。正式问题必须证明越过了预期数据边界，而不是只让模型复述公开信息。

### Improper Output Handling

模型输出进入 SQL、模板、浏览器、shell、代码解释器、Markdown/HTML 渲染器或下游 API 时，必须按不可信输入处理。安全责任落在消费输出的组件，而不是依赖模型“保证输出安全”。

### Excessive Agency

Agent 的工具权限应遵循最小权限：

- 读与写分离；
- 高影响动作需要显式确认；
- 工具作用域限定到具体资源；
- 避免长期、全局、跨租户凭证；
- 默认不允许模型自行扩大任务范围。

### RAG / Data Poisoning

关注索引来源、数据 provenance、更新权限、删除语义和租户隔离。检索内容应保留来源与信任等级，不能因为进入向量库就自动成为可信指令。

### Memory Poisoning

长期记忆或任务状态写入前应验证来源、主体和作用域。一次不可信输入不应永久改变 Agent 的权限规则、身份或安全策略。

## 3. Agent / Tool 安全

- 工具定义与参数 schema 必须可信且版本可追踪；
- 工具返回值属于不可信数据，不能直接提升为系统指令；
- 身份和授权由宿主应用控制，不能交给模型自行判断；
- 工具调用日志应记录主体、资源、动作与结果；
- 高风险能力采用审批、沙箱和最小权限组合，而不是单一提示词约束。

MCP 相关内容继续加载 `agent-mcp-security.md`。

## 4. 证据等级

```text
Signal -> Boundary Hypothesis -> Controlled Validation -> Impact -> Finding
```

仅“模型说它执行了”“模型答应绕过规则”“模型生成危险文本”不等于真实工具执行或数据越权。必须从应用层返回、工具日志、资源状态或跨主体差分中确认安全边界被突破。

## 5. Legacy

以下内容降为低优先级或非独立漏洞：

- 纯聊天越狱；
- 角色扮演让模型输出违规文本；
- 无工具、无敏感数据、无持久状态的 prompt 绕过；
- 仅凭模型声称“已执行”判断 RCE。

## 6. 防御基线

- 不可信内容与控制指令强分层；
- 工具调用结构化、最小权限、可审计；
- 高影响动作显式审批；
- RAG/Memory 保留 provenance 与租户边界；
- 模型输出进入解释器/渲染器/API 前做独立校验；
- 定期对 Prompt Injection、工具权限、跨用户数据和持久状态做回归测试。
