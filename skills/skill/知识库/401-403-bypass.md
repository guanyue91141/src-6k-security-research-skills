# 401 / 403 访问控制分流（2026）

> status: mixed  
> last_reviewed: 2026-09

打开是普通登录页或 SSO 壳时，不把“绕登录页面”当默认目标；优先回到业务 API、对象授权和认证链本身。

## 现代判断

401/403 只是服务端结果，不代表授权实现一定正确或错误。审查应区分：

- Authentication：当前主体是否被正确识别；
- Function-level authorization：当前主体能否调用该功能；
- Object-level authorization：目标对象是否属于可访问范围；
- Tenant boundary：组织/租户是否被服务端重新绑定；
- Gateway vs backend：网关与后端是否采用同一授权语义。

## 优先联动

- 业务 API 权限：`api-security-review.md`
- IDOR/BOLA/BFLA：`idor-test.md`
- 认证/恢复/会话：`authbypass-test.md`
- 路径与协议规范化：`api-gateway-test.md`、`http2-attacks-test.md`

## Legacy

仅通过修改方法、路径字符串或若干代理头反复尝试 401/403，不应成为现代默认 checklist。只有在目标架构确实存在网关/后端解析或授权差异时才提高优先级。
