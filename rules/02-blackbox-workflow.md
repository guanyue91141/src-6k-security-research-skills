# 黑盒 SRC 工作流

## 模式判定

- 固定 URL、文档或清单：锁面，只跟随该资产簇的业务 host、子域和 path，不主动扩展到无关集团。
- 只有品牌/集团：自由跳，进入 `04-target-discovery.md` 的种子闭环。
- 已登录目标：先对象图与换 ID，再做有差分面的注入、SSRF、XSS、RCE；未登录目标：先验证关键业务读，再换 ID。

## 进站顺序

1. 用几句话确认业务面、信任边界和当前会话；登录壳不是不可测结论，先找同 host 网关或跳转后的业务 host。
2. 抽取前端 JS 的 path、参数、盐/密文 ID、hidden 路由和演示账号，形成接口清单；回包里的 ID、URL、token 进入队列。
3. 对清单执行 `05-testing-policy.md` 的全类型矩阵。只有在参数有业务差分时才投递注入/SSRF/XSS/RCE 探针。
4. 中危发现先沿同一对象升链；完成本目标后再换站。FOFA 结果必须去重、去废、去非存活、过范围闸。

## 完成判据

每个存活目标至少完成：接口清单、认证/授权判定、全类型矩阵（无入口写 N/A 原因）、有差分参数的受控测试、证据状态更新。瘦壳、同构壳或纯登录 HTML 只做一眼证伪，不耗时空转。
