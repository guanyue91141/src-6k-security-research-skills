# 白盒源码审计工作流

<!-- Scope: 本地源码、GitHub 项目、反编译产物。Priority: L2。Owns: Phase 0-6 与黑盒隔离。Does Not Own: SRC 资产发现和正式报告排版。 -->

白盒输入不加载黑盒资产发现流程，按以下阶段推进：

0. **范围与构建**：识别语言、入口、依赖、测试方式和可运行验证条件。
1. **心智模型**：画出信任边界、输入→处理→存储、权限检查点、自研/依赖边界。
2. **变体分析**：查历史 CVE 和修复 commit，提取根因模式，全库搜索同形态并检查是否只修了一个入口。
3. **Sink 追踪**：枚举危险 sink，逆向参数来源，标记过滤/规范化点，验证可绕过性。
4. **框架专项**：按 Laravel/Spring/Django/Node 等实际栈选择 ORM、表达式、反序列化、JWT、原型链等专项。
5. **深层逻辑**：检查竞态、状态机、配置/硬编码密钥、依赖漏洞、被 revert 的安全修复。
6. **验证与交付**：每个发现回答输入可控性、前置条件、绕过、影响和可复现 PoC；按 confidence 归档，确认项才进入正式报告。

审计记录建议保存为 `state/findings.json`，字段至少包含 `type`、`location`、`source`、`sink`、`prerequisite`、`impact`、`confidence` 和 `status`。
